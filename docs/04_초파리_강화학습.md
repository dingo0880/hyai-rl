# 04. 초파리 강화학습 계획

> **한 줄 요약:** 초파리 버섯체 구조(감각 입력 → 케년세포로 펼치기 → 출력 뉴런, 도파민으로 학습)를 본뜬 작은 신경망이, "맞으면 설탕 / 틀리면 찌릿"만 받으면서 반짝반짝 작은 별을 외운다.

---

## 1. 강화학습 용어 ↔ 데모 ↔ 초파리 뇌

이 표는 화면의 "용어표"와 발표 슬라이드에도 그대로 쓴다.

| 강화학습 | 데모에서 | 초파리 뇌에서 |
|---|---|---|
| 환경 | 악보와 피아노 | 바깥 세상 |
| 상태 | 지금 몇 소절 · 몇 번째 박인지 + 방금 들린 음 | 감각 입력 (투사뉴런, PN) |
| 행동 | 8개 건반 중 하나 누르기 | 출력 뉴런(MBON)이 고른 행동 |
| 보상 | 맞으면 설탕 **+1**, 틀리면 찌릿 **−1** | 설탕 / 전기 자극 |
| 가치 (예상 보상) | "이 건반 치면 좋을 것 같은 정도" 막대 | MBON 활동 세기 |
| 예측오차 | 실제 보상 − 예상 보상 | **도파민 뉴런(DAN)의 발화** |
| 정책 | 막대 값으로 확률을 정해 건반 고르기 (softmax) | — |
| 에피소드 | 연주 한 번 (3번 틀리면 퇴장) | — |
| 학습 | 켜진 케년세포 → 고른 건반 연결을 도파민만큼 조정 | 도파민이 KC→MBON 시냅스 세기를 바꿈 |

**카페 비유 (발표용):** 주문서(상태)가 들어오면 바리스타 2,000명 중 100명만 손을 든다(케년세포). 손 든 사람들이 "이 메뉴 같아요"라고 투표해서 메뉴(건반)를 고른다. 손님 반응이 예상보다 좋으면(도파민 +) 그 100명의 의견을 더 믿고, 나쁘면(도파민 −) 덜 믿는다.

## 2. 모델 구조

```
[입력 PN 22개] --무작위 고정 연결--> [케년세포 KC 2,000개, 상위 5%만 켜짐]
                                          |
                                     학습되는 연결 W
                                          v
                                 [출력 MBON 8개 = 건반 8개]
                                          |
                                     softmax로 건반 선택
                                          |
                          보상 → 도파민(δ = 실제 − 예상) → W 수정
```

### 2.1 입력 (PN, 22개)
- 소절 번호 one-hot **6개** (1~6소절)
- 박 위치 one-hot **7개** (소절 안의 몇 번째 음)
- 방금 들린 음 one-hot **9개** (건반 8개 + "없음": 곡의 첫 음일 때)
  - 초파리가 **실제로 친 음**을 넣는다. 틀렸으면 틀린 음. ("내가 친 소리를 듣는다")
- 매 순간 정확히 **3개**가 켜진다.

### 2.2 케년세포 (KC)
- 개수 `N_KC = 2000` (실제 초파리 한쪽 버섯체도 약 2,000개)
- 연결: 각 KC는 PN 22개 중 **무작위 7개**와 연결, 연결 세기는 무작위 `0.5 ~ 1.5` (실제 KC도 평균 7개 정도의 입력을 받음)
- 발화: 입력 합 **상위 5% (`k = 100`개)만 1**, 나머지 0
  - 실제 초파리의 APL 뉴런(전체 억제)을 흉내 낸 k-WTA(상위 k개만 남기기)
  - 동점 처리: KC마다 고정된 아주 작은 노이즈(1e-6 수준)를 더해서 항상 같은 결과
- 연결과 발화 규칙은 **학습하지 않는다** (고정)
- 왜 이렇게? 적은 입력을 많은 세포로 펼치고 일부만 켜면, 비슷한 상황도 서로 다른 패턴이 돼서 덜 헷갈린다. (FlyHash와 같은 아이디어)
- 성능 팁: 가능한 상태가 6 × 7 × 9 = 378개뿐이라 `encode` 결과를 캐시해도 된다.

### 2.3 출력 (MBON, 8개 = 건반 수)
- `V[a] = (1/k) × Σ(켜진 KC i) W[a][i]` → 건반 a를 쳤을 때 **예상 보상**
- `W` 초기값은 전부 0 (갓 태어난 초파리는 아무것도 모름)

### 2.4 행동 선택 (정책)
- `p(a) = softmax(β × V[a])`, 기본 `β = 6` ("결단력")
- 처음엔 V가 전부 0 → 8개 건반 확률이 똑같이 1/8 → 완전 엉망
- 배울수록 V 차이가 벌어져서 저절로 확신 있게 친다
  - ε-greedy 같은 별도 스케줄이 필요 없다. 발표에서 "헤매는 게 줄어드는 것도 학습의 결과"라고 설명할 수 있다.

### 2.5 학습 규칙 (도파민 = 예측오차)
```
r = (a == 정답) ? +1 : -1
δ = r - V[a]                 // 도파민. +면 "예상보다 좋았다", −면 "예상보다 나빴다"
켜진 KC i마다: W[a][i] += α × δ     // 기본 α = 0.3
```
- 켜진 KC 100개를 모두 `α × δ`만큼 바꾸므로, 그 상태의 `V[a]`는 정확히 `α × δ`만큼 움직인다.
- **고른 건반의 연결만** 바꾼다 (안 고른 건반은 결과를 모르니까).
- 실제 초파리와 다른 점 (정보 창에 쓸 내용): 실제로는 도파민이 KC→MBON 시냅스를 주로 *약하게* 만들고, "다가가기"와 "피하기" MBON이 짝을 이룬다. 데모는 이해하기 쉽게 +/− 값을 갖는 연결 하나로 단순화했다.

### 2.6 의사코드
```js
function step(brain, obs, rng) {
  const active = brain.encode(obs);              // 켜진 KC 인덱스 k개
  const V = brain.values(active);                // 길이 8, 예상 보상
  const a = sampleSoftmax(V, brain.beta, rng);   // 건반 선택
  const r = (a === obs.target) ? 1 : -1;         // 설탕 or 찌릿
  const delta = r - V[a];                        // 도파민
  brain.learn(active, a, delta);                 // W[a][i] += alpha * delta
  return { active, V, a, r, delta };
}
```

## 3. 에피소드 규칙

| 구분 | 연습 (학습 O) | 연주회 (학습 X) |
|---|---|---|
| 시작 | 곡 처음부터 | 곡 처음부터 |
| 실수 제한 | **3번 틀리면 퇴장** | 없음 (곡 전체를 들려줌) |
| 행동 선택 | softmax(β) 샘플링 | 같은 softmax(β) 샘플링 |
| 난수 | 학습용 RNG 하나를 계속 사용 | 스냅샷마다 고정 시드 `1000 + 회차` |

- 실수 3번 퇴장 규칙 덕분에, 처음엔 곡 앞부분만 연습하고 실력이 늘수록 점점 뒤까지 가게 된다. → **"점점 더 멀리 치는" 모습과 성장 지도의 "금색이 왼쪽부터 번지는" 그림이 자연스럽게 나온다.**
- 옵션 "실수 없는 모드": 연주회를 argmax로 연주. 발표 기본값은 off (초기의 엉망진창이 더 웃기니까).

## 4. 목표 학습 곡선

### 4.1 사전 검증 결과 (이 계획서를 쓰면서 위 설계 그대로 시뮬레이션함)
기본 파라미터 `N_KC=2000, k=100, fanIn=7, α=0.3, β=6, 실수 제한 3`, 시드 42 / 7 / 123, 연주회는 단계마다 5번 평균.

| 연습 회차 | 연주회 정답률 (시드 42 / 7 / 123) | 첫 소절 정답률 | 연습 중 평균 도달 음 수 (구간) |
|---|---|---|---|
| 0 | 11% / 11% / 11% | 9% | 0~5회: 3.0 ~ 4.4 |
| 5 | 15% / 18% / 15% | 23 ~ 37% | 5~15회: 4.5 ~ 7.4 |
| 15 | 25% / 29% / 27% | 63 ~ 94% | 15~40회: 12.9 ~ 13.8 |
| 40 | 45% / 48% / 52% | 100% | 40~80회: 23.3 ~ 29.2 |
| 80 | 86% / 77% / 89% | 100% | 80~150회: 39.5 ~ 41.1 |
| 150 | 97% / 96% / 100% | 100% | 150~300회: 41.6 ~ 41.8 |
| 300 | 100% / 100% / 100% | 100% | — |

평균 |도파민| (놀람 크기): 0~5회 약 **0.9** → 40~80회 약 **0.2** → 150~300회 약 **0.01**. "잘할수록 놀랄 일이 줄어든다"가 숫자로 보인다.

→ 이 숫자는 **달성 가능하다는 근거**다. 구현이 조금 달라도 아래 4.2 범위에 들어오면 된다.

### 4.2 스냅샷별 목표 범위 (시드 42 기준)

| 회차 | 화면 별명 | 연주회 정답률 목표 | 들었을 때 느낌 |
|---|---|---|---|
| 0 | 갓 태어난 초파리 | 10 ~ 20% | 완전 소음 |
| 5 | 건반이 뭔지 앎 | 12 ~ 25% | 첫 두세 음만 가끔 맞음 |
| 15 | 첫 소절 성공 | 전체 20 ~ 40%, **첫 소절 60% 이상** | "도도솔솔라라솔"까지 들리고 그 뒤는 엉망 |
| 40 | 절반까지 | 35 ~ 60% | 앞 절반은 그 노래 |
| 80 | 끝까지는 감 | 65 ~ 92% | 끝까지 가는데 삑사리 몇 번 |
| 150 | 거의 완벽 | 92 ~ 100% | 한두 번 실수 |
| 300 | 초파리 마에스트로 | 97 ~ 100% | 완주 |

### 4.3 튜닝 가이드 (범위를 벗어나면)
1. **β (결단력)**: 최종 정확도가 낮으면 올린다 (범위 3 ~ 8)
2. **α (학습률)**: 너무 빨리 배우면(15회에 이미 완주) 내리고, 너무 느리면(300회에 90% 미만) 올린다 (범위 0.1 ~ 0.5)
3. **k, N_KC**: 비슷한 위치끼리 헷갈림이 너무 많거나 적을 때 조정
4. 스냅샷 회차(0·5·15·40·80·150·300) 자체를 바꾸는 것도 허용. 바꾸면 `docs/02_기능.md`의 칩 이름도 같이 고친다.

## 6. (선택, Phase 6) 대치동 초파리 vs 산골 초파리

도입부의 수험생 비유를 다시 꺼내는 비교 모드.

| | 대치동 초파리 | 산골 초파리 |
|---|---|---|
| 비유 | 옆에서 선생님이 매 음마다 "맞아 / 틀려" | 소절이 다 끝나야 "몇 개 맞았다"만 앎 |
| 보상 | 매 음 +1 / −1 (촘촘한 보상) | 소절 끝에만 `R = (맞은 수 × 2 − 친 음 수) / 친 음 수` (−1 ~ +1, 드문 보상) |
| 학습 | 위 2.5 규칙 | 아래 자격 흔적 규칙 |

**산골 초파리 학습 규칙 (자격 흔적, eligibility trace)**
- 소절 안에서 고른 (켜진 KC, 고른 건반)을 흔적 목록에 저장, 매 음마다 이전 흔적의 세기 `e *= λ` (`λ = 0.8`), 새 흔적은 `e = 1`
- 소절 끝 (또는 퇴장 시점): `δ = R − (그 소절에서 고른 건반들의 V 평균)`
- 흔적마다 `W[a][i] += α × δ × e`, 그 후 흔적 비움
- 실수 3번 퇴장 규칙은 똑같이 적용 (환경이 판단, 초파리는 소절 끝까지 모름)

**사전 검증 결과 (같은 파라미터, 300회 연습 후 연주회)**
| | 0회 | 40회 | 80회 | 150회 | 300회 |
|---|---|---|---|---|---|
| 대치동 (시드 42) | 11% | 45% | 86% | 97% | 100% |
| 산골 (시드 42 / 7 / 123) | 11% | 12 ~ 17% | 20 ~ 23% | 26 ~ 29% | 33 ~ 36% |

→ "피드백을 자주, 구체적으로 받을수록 훨씬 빨리 배운다"는 게 확실히 보인다. (강화학습의 **보상 설계 / 드문 보상 문제**)

자동 검사 추가: 산골 300회 정답률이 대치동 300회보다 30%p 이상 낮을 것.

## 7. 코드 구조와 인터페이스

```js
// js/core/rng.js
FlyPiano.makeRng(seed) -> { next(): [0,1), int(n), pick(arr) }   // mulberry32

// js/rl/song.js
FlyPiano.SONG       // [{ note: 0~7, beats: 1|2, phrase: 0~5, beat: 0~6 }, ...] 42개
FlyPiano.KEY_NAMES  // ['도','레','미','파','솔','라','시','높은 도']

// js/rl/env.js
class PianoEnv {
  constructor(song, { maxMistakes = 3 })
  reset()
  observe()  -> { phrase, beat, prevNote, target, t }
  step(a)    -> { reward, correct, done, mistakes, t }
}

// js/rl/brain.js
class MushroomBody {
  constructor(cfg, rng)               // cfg: { nKC, k, fanIn, alpha, beta, nKeys }
  encode(obs)            -> Int32Array(k)        // 켜진 KC 인덱스
  values(active)         -> Float32Array(nKeys)  // 예상 보상
  act(values, rng)       -> a
  learn(active, a, delta)
  snapshot()             -> Float32Array 복사본
  load(snapshot)
}

// js/rl/trainer.js
class Trainer {
  constructor(cfg, seed)
  runEpisode({ learn = true, onStep })   // onStep(stepInfo) — 02 문서의 이벤트 형식
  train(n)                               // 빨리 연습
  concert(snapshot, seed, { greedy = false, onStep })
  history                                // 회차별 { reached, accuracy, meanAbsDelta }
  snapshots                              // { [회차]: Float32Array }
}
```

- 모든 `js/rl/*.js`, `js/core/rng.js` 끝에 Node export:
  `if (typeof module !== 'undefined') module.exports = { ... };`
- `W`는 `Float32Array(nKeys × nKC)` 하나로.
- **UI는 RNG를 직접 쓰지 않는다.** 학습 결과는 연습 속도(×1 / ×100)와 상관없이 같아야 한다.
